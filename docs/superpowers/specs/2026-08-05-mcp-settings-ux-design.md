# UX вкладок MCP и Настроек: каталог и карточки вместо форм, дифф-полоса вместо колонки

**Дата:** 2026-08-05
**Статус:** утверждено
**Направление:** «Верстак» (вариант A из обсуждения 2026-08-05; из варианта B взят только сегментированный контрол риска)

## Задача

Обе вкладки построены как вертикальная форма в колонке шириной 620–640px внутри полноэкранного контейнера. Конкретные следствия:

1. **MCP не помогает на входе.** Экран открывается пятью пустыми полями (`web/src/screens/McpScreen.tsx:128-192`). Человек копирует из README MCP-сервера строку `uvx mcp-server-fetch` целиком, а форма требует разрезать её на «Команда» и «Аргументы» руками. Пустое состояние — фраза «Пока не подключено ни одного сервера» и ничего больше.
2. **Результат проверки спрятан.** Discovery возвращает список инструментов — единственное, ради чего кнопка нажимается, — и он рисуется одной мелкой строкой внизу через запятую (`McpScreen.tsx:211-221`).
3. **Ширина не используется.** `.mcp__body` — `max-width: 640px` (`McpScreen.css:1-3`), справа пустое полотно. То же в Настройках: `.field` ограничен 620px (`SettingsScreen.css:58-61`), а `.settings__body` растянут между навигацией и дифф-панелью.
4. **Дифф-колонка занимает 344px всегда** (`SettingsScreen.css:101-108`), даже когда изменений ноль. Рядом — оранжевая `btn--primary` «Сохранить», которая при нуле изменений `disabled`: главный CTA экрана в норме выключен.
5. **Строка провайдера несёт шесть кнопок** (`SettingsScreen.tsx:455-504`). «Изменить» не редактирует строку, а заполняет форму в самом низу — контекст телепортируется, и человек теряет, что именно правит.

## Решение

Бэкенд не меняется. Ключевое наблюдение: `POST /mcp/test` (`gateway/api.py:828`) принимает `command`/`args`/`env_refs`, а не имя сервера, — значит тем же вызовом проверяется и уже сохранённый сервер, если взять его поля из `GET /mcp`. Живость и список инструментов сохранённого сервера получаются без новых эндпоинтов и без изменения схемы конфига.

### Вкладка MCP

#### Поле вставки и парсер

Пять полей ввода сворачиваются в одно: «Вставьте команду или JSON». Парсер `web/src/model/mcpPaste.ts`, функция `parsePaste(text): ParsedServer | null`, где

```ts
interface ParsedServer {
  name: string;      // предложение, редактируемое
  command: string;
  args: string[];
  envRefs: string[];
}
```

Распознаёт три формы:

- **shell-строка** — `uvx mcp-server-fetch`, `npx -y @modelcontextprotocol/server-github`. Токенизация с уважением к одинарным и двойным кавычкам; первый токен — команда, остальные — аргументы.
- **конфиг Claude Desktop** — объект с ключом `mcpServers`; берётся первая запись. Самый частый источник копипасты: README MCP-серверов печатают именно этот блок.
- **одиночный объект сервера** — `{"command": …, "args": […], "env": {…}}`.

Имя предлагается из аргументов: последний сегмент пути пакета с отброшенным префиксом `mcp-server-`/`server-` (`@modelcontextprotocol/server-github` → `github`, `mcp-server-fetch` → `fetch`); если вывести не удалось — имя команды. Поле имени редактируемое.

**Значения `env` из вставленного JSON отбрасываются; сохраняются только имена ключей** — они и есть `env_refs`. Правило жёсткое: человек копирует чужой конфиг вместе с живым токеном, и тихая запись этого токена в `svarog.yaml` была бы утечкой. Значения секретов остаются в secret store, в конфиг идёт ссылка — то, что модель `McpServer` (`web/src/api/types.ts:164-170`) и так описывает.

Разобранный результат показывается под полем как редактируемые поля (имя, команда, аргументы, секреты) в свёрнутом блоке «Уточнить» — парсер может ошибиться, и правка должна быть возможна без возврата к ручному вводу. Если `parsePaste` вернул `null`, блок раскрыт по умолчанию и работает как нынешняя форма.

#### Проверка как состояние, а не кнопка-близнец

«Проверить» стоит у поля вставки. Результат — панель под ним:

- успех: заголовок «Сервер ответил — N инструментов» и чипы с именами инструментов (все, с переносом; не строка через запятую);
- отказ: текст ошибки из `McpTest.error`.

«Подключить» остаётся доступной без проверки — проверка не обязательна (это отличает вариант A от отвергнутого B). Но если последняя проверка завершилась отказом, первый клик по «Подключить» меняет надпись на «Всё равно подключить?», второй сохраняет. Приём уже используется при удалении провайдера (`SettingsScreen.tsx:296-301`) и выбран по той же причине: тестируем, не блокирует вкладку нативным диалогом.

Состояние проверки сбрасывается при любом изменении команды или аргументов — иначе зелёная панель относилась бы к другой команде.

#### Каталог пресетов

Константа `web/src/model/mcpPresets.ts`: массив `{ id, title, command, args, risk, envRefs, hint }` для `fetch`, `filesystem`, `github`, `postgres`, `playwright`, `sqlite`, `memory`, `time`. Клик по карточке пресета заполняет поле вставки его командой (не сохраняет сразу — человек должен видеть, что подключает).

Каталог показывается, пока поле вставки пусто. Это делает пустое состояние вкладки предложением, а не констатацией.

Пресеты — фронтовая константа, не эндпоинт: список меняется вместе с UI, версионируется вместе с ним и не требует ни сети, ни миграции конфига.

#### Карточки серверов

Список `GET /mcp` рисуется сеткой: `grid-template-columns: repeat(auto-fill, minmax(280px, 1fr))`, контейнер `max-width: 1100px`. На карточке:

- имя и риск-бейдж;
- команда с аргументами моноширинным, в одну строку с усечением;
- имена `env_refs`, если есть;
- кнопка «Инструменты» — вызывает `mcpTest` с сохранёнными полями сервера, разворачивает чипы и ставит точку живости (зелёная/красная);
- «Удалить» с двухкликовым подтверждением.

**Живость проверяется по клику, не автоматически при открытии вкладки.** Автопроверка всех серверов означала бы запуск N процессов при каждом заходе — дорого и неожиданно для человека, который зашёл посмотреть список.

#### Риск сегментированным контролом

`select` с четырьмя словами заменяется на четыре сегмента `low | medium | high | critical` и строку последствия под ними.

Формулировки сверены с `policy/engine.py` и отличаются от нынешнего текста экрана. По умолчанию **любой** MCP-инструмент требует подтверждения в любом режиме автономии — ветка `action_type.startswith("mcp.")` (`engine.py:207-214`, §9) перехватывает вызов до того, как уровень риска что-либо решит. Уровень риска отвечает не на вопрос «спросят ли», а на вопрос «можно ли это ослабить правилом или профилем»:

- low, medium — подтверждение по умолчанию; правилом `notify` в `svarog.yaml` ослабляется до уведомления;
- high — то же, но в режиме `supervised` ослабить нельзя (`engine.py:191-198`);
- critical — подтверждение всегда, ни правилом, ни профилем, ни режимом не отключается (`engine.py:161-168`).

Текущая подпись экрана «риск задаёт профиль по умолчанию (high — с подтверждением человека)» (`McpScreen.tsx:100-103`) подразумевает, что low/medium проходят молча, — это неверно и заменяется. Вводный абзац сокращается до одного предложения: детали переехали к контролу, где принимается решение.

### Вкладка Настроек

#### Дифф — полоса снизу, а не колонка

`.diffpane` теряет `flex: 0 0 344px` и позицию третьей колонки.

- `changes === 0` и нет ошибки — панели нет вообще. Вместе с ней исчезает выключенный оранжевый CTA.
- `changes > 0` — внизу контентной области появляется полоса: число изменений, путь файла, «Показать дифф», «Сохранить», «Отменить». «Показать дифф» раскрывает панель вверх над полосой.

Мобильная шторка (`SettingsScreen.css:200-231`) уже работает именно так; изменение делает это поведение единственным на всех ширинах и удаляет ветку `.settings__sheet-button`, существующую только ради узкого экрана.

Ошибка валидации (`error !== null`) полосу показывает — иначе сообщение «изменения не пройдут проверку» негде отрисовать.

#### Центрирование контента

`.settings__body` получает внутреннюю обёртку `max-width: 720px; margin: 0 auto`. Разрыв между полями и правым краем на широком экране закрывается.

#### Провайдер — карточка

Строка с шестью кнопками (`SettingsScreen.tsx:407-533`) становится карточкой:

- видимое: имя, бейдж «по умолчанию», модель, base_url, кнопки «По умолчанию» и «Модели»;
- в меню «⋯»: «Проверить», «Изменить», «Переименовать», «Удалить».

«Изменить» раскрывает форму **внутри карточки**, а не заполняет форму внизу экрана. Форма внизу остаётся, но только для добавления нового провайдера, и её заголовок меняется с «Добавить / обновить» на «Добавить провайдера». Статусная строка `startEdit` (`SettingsScreen.tsx:261-269`), объясняющая телепорт, удаляется — объяснять больше нечего.

Меню «⋯» — раскрывающийся блок в карточке, не всплывающий поповер: поповер требует управления фокусом, закрытия по Escape и клику вне, и это цена, которую незачем платить ради четырёх кнопок.

#### Общий модуль риска

`web/src/model/risk.ts`: порядок уровней, русские подписи, описания последствий (используются и в сегментированном контроле MCP). Цвета — классы `.risk--{level}` в `web/src/styles/base.css`.

Шкала берётся из уже существующей в `SkillsScreen.css:39-50` (`--ok` → `#d89a79` → `--bad`) и достраивается уровнем `critical`. `SkillsScreen` переводится на общие классы; `RISK_LABELS` из `SkillsScreen.tsx:52` переезжает в модуль.

## Границы

Не входит в эту работу (это отвергнутое направление B):

- единая модель сохранения — провайдеры, исполнители и секреты продолжают писать в файл сразу, минуя дифф;
- поиск по настройкам;
- редактируемый yaml и двусторонняя подсветка форма↔yaml (направление C).

Бэкенд, схема `svarog.yaml` и контракты API не меняются. Список инструментов сервера в конфиге не сохраняется — чипы запрашиваются по клику.

## Тестирование

Существующие `McpScreen.test.tsx`, `SettingsScreen.test.tsx` и `SkillsScreen.test.tsx` обновляются под новую разметку. Добавляется:

- `web/src/model/mcpPaste.test.ts` — три формы ввода, кавычки в shell-строке, вывод имени, **отбрасывание значений `env` при сохранении ключей**;
- в `McpScreen.test.tsx` — клик по пресету заполняет поле; проваленная проверка требует второго клика по «Подключить»; правка команды сбрасывает результат проверки; «Инструменты» на карточке сервера вызывает `mcpTest` с полями этого сервера;
- в `SettingsScreen.test.tsx` — при нуле изменений полосы нет; при правке поля она появляется с числом; «Изменить» на карточке провайдера раскрывает форму в карточке и не трогает форму добавления.
