# Поле ввода: слэш-команды, `@`-файлы, вложения и точные подписи

**Дата:** 28 июля 2026
**Статус:** утверждён
**Контекст:** веб-интерфейс «Горн» (`2026-07-27-web-ui-gorn-design.md`),
выбор исполнителя и модели (`2026-07-27-composer-executor-and-model-design.md`)

## Задача

Поле ввода должно вести себя как в CLI-чате: слэш-команды с подсказками,
ссылки на файлы через `@` с автодополнением, вложения к сообщению
(скриншот, PDF, docx, xlsx). Плюс две правки подписей: исполнитель
выбирается не из пары «нативный цикл / внешний агент», а по адаптерам, и
автономия называется так же, как в «Настройках».

## Что уже есть в CLI

Почти всё. Это меняет форму работы: выносим наружу, а не пишем заново.

| Что | Где |
|---|---|
| Режимы подсказок IDLE/SLASH/AT, парсинг токена под курсором | `cli/chat_completion.py: detect_completion` |
| Подсказки команд и файлов | `cli/chat_completion.py: slash_suggestions, at_suggestions` |
| Обход workspace с фильтром тяжёлых каталогов | `cli/chat_completion.py: list_workspace_files` |
| Реестр слэш-команд | `cli/chat_commands.py: COMMANDS` |
| Список доступных исполнителей + detection адаптеров по `PATH` | `cli/chat_display.py: chat_status_view` |
| Смена адаптера вместе с образом | `cli/chat_settings.py: apply_executor_label` |
| Чтение pdf/docx/xlsx и показ изображений модели | `tools/document_tools.py` |

Два факта отсюда определяют решения ниже.

**`@` вставляет путь, а не содержимое.** `at_suggestions` возвращает
`value=f"@{path}"`, и подстановки текста дальше нет: агент видит
`@src/foo.py` как обычный текст и сам решает прочитать файл. В вебе — так
же.

**Смена адаптера обязана менять образ.** `executor.external.image`
специфичен для адаптера (`svarog/agent-claude` против
`svarog/agent-opencode`); иначе в sandbox остаётся CLI прежнего агента и
запуск падает `command not found`. CLI подменяет образ **только если
текущий — один из дефолтов `svarog init`**, чтобы не затирать
пользовательский (`chat_settings.py:74`). Под `codex` образа в проекте
нет вовсе, и CLI его не трогает.

## Решение

### 1. Автономия — сырые значения

Композер показывает `supervised`, `auto`, `yolo` — ровно то, что
показывает форма «Настроек» (она берёт варианты из схемы, `settings.py`
`_kind_and_choices`). `AUTONOMY_LABELS` из `web/src/api/types.ts`
удаляется вместе с русскими подписями.

### 2. Исполнитель — по адаптерам

Override получает **отдельное поле** `adapter`, а не строку-метку вида
`external/claude-code`:

```python
class SendMessageRequest(BaseModel):
    ...
    executor: Literal["native", "external"] | None = None
    adapter: Literal["claude-code", "codex", "opencode"] | None = None
```

Отступление от формата CLI намеренное. Метка CLI кодирует ещё и sandbox
(`native/docker` против `native/local`), а sandbox остаётся в
«Настройках». Отдельное поле не ломает уже записанные `Run.meta` от
прошлой работы и не требует парсинга строки при восстановлении.

`RunOverride` получает поле `adapter`; `to_meta`/`from_meta` — как у
остальных, терпимо к отсутствию и мусору.

`apply_override` при заданном `adapter`:

- требует `executor="external"` (или уже `external` в конфиге) — иначе
  `OverrideError`: адаптер без внешнего исполнителя ничего не значит;
- подменяет `executor.external.adapter`;
- подменяет `executor.external.image` **только** если текущий образ есть
  среди дефолтов `svarog init` (`DEFAULT_CLAUDE_IMAGE`,
  `DEFAULT_OPENCODE_IMAGE` из `scaffold.py`). Кастомный образ не трогаем:
  человек поставил его руками, и подмена молча увела бы запуск в другой
  контейнер;
- если для адаптера дефолтного образа нет (`codex`) и текущий образ —
  чужой дефолт, это `OverrideError` с объяснением: под codex образ нужно
  собрать и указать в конфиге.

Список вариантов для селекта отдаёт новый эндпоинт
`GET /executors` → `list[ExecutorOptionView]`:

```python
class ExecutorOptionView(BaseModel):
    value: str          # "native" | "claude-code" | "codex" | "opencode"
    kind: Literal["native", "external"]
    adapter: str | None
    available: bool     # CLI адаптера найден в PATH или он прописан в конфиге
    is_active: bool     # соответствует текущему конфигу
```

Логика — та же, что у `chat_status_view`: `native` всегда, плюс каждый
адаптер, который прописан в конфиге **или** чей бинарь нашёлся в `PATH`.
Недоступные адаптеры показываются заблокированными с подсказкой, а не
скрываются: иначе человек не понимает, почему в списке нет codex.

### 3. Слэш-команды и `@`-файлы

**Реестр веба — свой, шесть команд.** `/quit` и `/mode` отпадают (некуда
выходить; режим local/cloud в вебе не переключается). `/fork` отложен:
в CLI форк держит историю в памяти процесса и заводит пустую сессию, а
шлюз собирает историю из трассы по `session_id` — форк потребовал бы
менять сборку истории (цепочка `forked_from` или копирование сообщений).
Это отдельная работа, а не строка в реестре.

| Команда | Действие |
|---|---|
| `/help` | список команд в ленте |
| `/new` | новый чат |
| `/sessions` | перевести фокус на список чатов; на узком экране сперва выдвинуть панель |
| `/executor` | раскрыть селект исполнителя |
| `/policies` | раскрыть селект автономии |
| `/copy` | скопировать последний ответ в буфер |

`/executor` и `/policies` дублируют селекты подвала намеренно: это
клавиатурный путь к тому же действию, привычный по CLI.

Реестр живёт на сервере (`gateway/commands.py`) и отдаётся через
`GET /commands` → `list[SlashCommandView]` (`name`, `usage`, `help`) —
чтобы подсказки и справка не разошлись между клиентом и сервером.

**Определение режима — на клиенте.** `detect_completion` — двадцать
строк чистой логики; ходить на сервер за каждым нажатием клавиши нельзя.
Портируется в `web/src/model/completion.ts` один в один, включая
приоритет `@` над `/` и правило «слэш только в первом токене строки».
Тесты повторяют случаи из `tests/test_chat_completion.py`.

**Список файлов — с сервера.** У браузера нет доступа к файловой
системе. `GET /sessions/{id}/files?q=<токен>` → `list[FileSuggestionView]`
(`path`, `is_dir`), поверх существующих `list_workspace_files` и
`at_suggestions`. Корень — workspace **сессии**, не сервиса.

Клиент запрашивает файлы при входе в режим AT и кеширует ответ на
сессию; фильтрация по мере набора — на клиенте, по уже полученному
списку (лимит `list_workspace_files` — 800 файлов, этого достаточно и
избавляет от запроса на каждую букву).

**Меню.** Появляется над полем ввода, до восьми строк со скроллом. `↑`/`↓`
— перемещение, `Tab` и `Enter` — вставить, `Esc` — закрыть. Пока меню
открыто, `Enter` вставляет подсказку, а не отправляет сообщение —
иначе первое же дополнение улетит агенту. Строка: слева значение, справа
описание (для команд) или «файл».

### 4. Вложения к сообщению

`POST /sessions/{id}/attachments` (multipart) → `AttachmentView` (`path`,
`name`, `size_bytes`, `mime`, `too_large_for_vision`).

**Вложение — это файл, но человек про это не думает.** Любой путь к
модели упирается в файл в workspace: `ChatMessage` в LLM-слое несёт
`role` и `content: str`, без блоков (`llm/provider.py:52`), а картинка
доходит до модели единственным способом — `read_image` читает её из
рабочей папки и возвращает `blocks=[{"type": "image", …}]`. Внешний агент
тоже видит только смонтированное рабочее дерево. Поэтому вопрос не «файл
или вложение», а куда его класть и как показывать.

- **Куда.** `.attachments/` внутри workspace сессии. Точка в начале имени
  значит, что `list_workspace_files` каталог пропускает — вложения не
  засоряют подсказки `@`. Имя на диске получает короткий префикс-хеш,
  поэтому коллизий нет и отказывать при повторной загрузке не нужно;
  человеку показывается исходное имя.
- **Не в git.** Путь дописывается в `.git/info/exclude`, а не в
  `.gitignore`: это локальный файл, он не отслеживается и не появится в
  чужом diff. Запись идемпотентная. Рабочая папка без git — шаг
  пропускается. При `git.separate_git_dir` настоящий git-каталог
  резолвится через `GitRepo`, а не как `workspace/.git`.
  Без этого автокоммит (`_autocommit`, Flow C) утащил бы скриншот бага в
  историю task-ветки.
- **Как показывается.** В ленте — миниатюра под текстом сообщения, а не
  строка `@путь`. Композер показывает чип с исходным именем и крестиком
  до отправки.
- **Как узнаёт агент.** `POST …/messages` принимает
  `attachments: list[str]`; сервер дописывает к тексту задачи одну
  строку с путями и напоминанием прочитать их `read_image` /
  `read_document`. Строка попадает в трассу — то есть в ленте видно ровно
  то, что получил агент, без скрытых добавок.

Ограничения — все обязательные:

- **Расширения по белому списку**, собранному из того, что инструменты
  действительно умеют, а не выдуманному: `_IMAGE_MIME` (`.png .jpg .jpeg
  .gif .webp`) и `_DOCUMENT_SUFFIXES` (`.pdf .docx .xlsx .xls .pptx .html
  .htm .epub .csv`) из `document_tools.py`, плюс текстовые `.txt .md
  .json .yaml .yml`. Список строится из этих констант, а не копируется —
  иначе он разойдётся с инструментами при первом же расширении набора.
  Чужое расширение → 415 со списком допустимых.
- **Потолок размера** — 25 MB на файл, константа рядом с эндпоинтом.
  Отдельно: `read_image` не примет картинку больше 5 MB, поэтому при
  загрузке изображения свыше этого порога ответ несёт
  `too_large_for_vision=true`, а интерфейс — предупреждение. Это не
  отказ: файл может понадобиться агенту как исходник для `pdftoppm`.
- **Имя обеззараживается**: берётся только базовое имя, отбрасываются
  разделители пути и `..`; итоговый путь обязан лежать внутри
  `.attachments/` (`is_relative_to`), иначе 400.
- **Запуск в сессии идёт** → 409, как у удаления чата: класть файлы под
  работающий агент нельзя.

Коллизий имён на диске нет по построению (префикс-хеш), поэтому 409 на
существующий файл не нужен — повторная загрузка того же скриншота просто
даёт второе вложение.

Интерфейс: кнопка-скрепка рядом с микрофоном, drag-and-drop на поле
ввода и вставка из буфера (`paste` с картинкой — главный путь для
скриншота). Прикреплённое показывается чипами над полем: миниатюра для
картинки, значок и имя для документа, крестик — убрать до отправки. Во
время загрузки чип показывает прогресс; ошибка — на месте чипа и не
мешает отправить сообщение без него.

## Обработка ошибок

| Ситуация | Код | Текст |
|---|---|---|
| Адаптер без внешнего исполнителя | 422 | `OverrideError` |
| Адаптер без известного образа (codex) | 422 | что собрать и куда прописать |
| Расширение не в белом списке | 415 | список допустимых |
| Файл больше 25 MB | 413 | размер и потолок |
| Имя выходит за `.attachments/` | 400 | санитизированное имя |
| В сессии идёт запуск | 409 | как при удалении чата |
| Неизвестная сессия | 404 | id |
| Вложение из другой сессии в `messages` | 400 | путь |

## Тесты

**Сервер.** `apply_override` с адаптером: подмена адаптера и образа;
кастомный образ не трогается; codex без образа отклоняется; адаптер без
external отклоняется. Round-trip `adapter` в meta. `GET /executors`:
native всегда, настроенный адаптер всегда, недоступный — с
`available=false`. `GET /commands` возвращает шесть. `GET
/sessions/{id}/files`: пути относительные, тяжёлые каталоги отфильтрованы,
`.attachments/` в подсказки не попадает, корень — workspace сессии, а не
сервиса.

Вложения: успех кладёт файл в `.attachments/` и возвращает исходное имя
отдельно от пути на диске; повторная загрузка того же имени даёт два
разных пути; каждая строка таблицы ошибок — свой тест; обход пути
(`../../etc/passwd`, `foo/../../bar`) отклоняется. Отдельно —
**`.git/info/exclude`**: путь дописан, повторная загрузка не дублирует
строку, рабочая папка без git не роняет загрузку, а при
`git.separate_git_dir` запись идёт в настоящий git-каталог. И
**интеграционный**: после запуска с вложением `git status` рабочего
дерева чист — иначе автокоммит утащит скриншот в историю ветки, ради чего
всё это и делается.

`send_message` с `attachments`: пути дописаны к тексту задачи, путь из
чужой сессии отклонён.

**Клиент.** `detect_completion` — случаи из `tests/test_chat_completion.py`
один в один. Меню: фильтрация, `↑`/`↓`, `Tab`/`Enter` вставляют и не
отправляют, `Esc` закрывает. Селект исполнителя: недоступный адаптер
заблокирован с подсказкой. Автономия показывает сырые значения.
Вложения: чип появляется после загрузки и убирается крестиком; отправка
несёт пути; ошибка загрузки показана и не блокирует отправку без этого
вложения; картинка в ленте рисуется миниатюрой, а не строкой пути.

## Что не делается

- `@` не подставляет содержимое файла в текст сообщения — как в CLI,
  это ссылка, а читает файл агент инструментом.
- Sandbox из композера не переключается: в CLI он часть метки
  исполнителя, здесь остаётся в «Настройках».
- Путь к модели по-прежнему только через `read_image`: композер шлёт путь
  к файлу, а не картинку, второго механизма нет и не планируется — так
  проще и одинаково работает с любым исполнителем. Это стоит одного
  лишнего вызова инструмента. Изменилось то, что результат самого вызова
  теперь доезжает до модели картинкой, а не только текстом: `ChatMessage`
  несёт `images`, и провайдер строит из них часть запроса `image_url`
  (`2026-07-28-native-vision-design.md`). Это работает и на нативном
  цикле, не только через внешнего агента.
- `/fork` — нужна серверная поддержка форка сессии (см. §3).
- `.attachments/` не чистится по расписанию. Файлы маленькие, лежат вне
  git и вне подсказок; retention добавится, если папка начнёт расти.
- Файл, с которым агент должен **работать** (исходник, документ для
  правки), по-прежнему кладётся в рабочую папку руками или самим агентом:
  вложение — это то, что человек показывает, а не то, что становится
  частью проекта.
