# Живое автоназвание чатов: черновик сразу, уточнение после ответа, WS-пуш и анимация

**Дата:** 2026-08-05
**Статус:** утверждено
**База:** развитие фичи `2026-08-04-chat-autotitle-design.md` (вариант B из обсуждения 2026-08-05)

## Задача

Сейчас название генерируется один раз — после завершения первого run'а — и доезжает до UI только поллингом, который к этому моменту уже остановлен (поллинг живёт лишь пока чат busy, `web/src/App.tsx:118-127`): название появляется с опозданием или после ручного действия. Нужно:

1. **Черновик сразу**: название генерируется по одному только вопросу, как только пользователь отправил первое сообщение.
2. **Уточнение после ответа**: когда первый run завершился, название перегенерируется по вопросу+ответу.
3. **Мгновенная отрисовка**: обновления приходят в UI пушем по WebSocket (не поллингом) и печатаются посимвольно (анимация набора текста) в сайдбаре и топ-баре.

## Решение

### Почему не событие в ленте run'а

Per-run стрим (`storage/events.py`) терминируется на `run_finished` (`_is_terminal`, `events.py:26`), сервер закрывает WS после исчерпания стрима (`api.py:630-631`), а уточнённое название пишется **после** `_publish_finished`. Событию некуда прийти. Двигать генерацию до `run_finished` — значит задерживать видимое завершение ответа на латентность aux-модели. Поэтому — отдельный канал.

### Канал событий сессий (бэкенд)

Новый модуль `src/svarog_harness/gateway/session_events.py`: класс `SessionEventHub` — простой fan-out без истории (подписчик получает только события с момента подписки; начальное состояние покрывает `GET /sessions`):

- `subscribe() -> AsyncIterator[dict]` — очередь на подписчика, ограниченная (например, 100), при переполнении событие подписчику молча дропается (события — только косметика, актуальное состояние всегда в БД);
- `publish(event: dict) -> None` — синхронный, неблокирующий.

Владение хабом — по границе доверия:

- `GatewayService` получает hub в конструкторе (поле с `default_factory=SessionEventHub`).
- **WorkspaceHub** (multi-root, один пользователь): один общий hub на все сервисы всех корней — Nav показывает сессии всех корней, события тоже должны приходить все.
- **TenantHub** (multi-tenant): hub per-tenant — жильцы не видят чужих названий. Общий hub между тенантами запрещён.

Эндпоинт `WS /sessions/events` в `gateway/api.py`: аутентификация как у `/runs/{id}/events` (token в query или Authorization; отказ — close 1008 до accept), затем бесконечный цикл `send_json` по `hub.subscribe()`. Соединение живёт, пока клиент его держит.

Событие одно: `{"type": "session_title", "session_id": ..., "title": ..., "phase": "draft" | "final"}`. Публикуется в момент записи названия в БД (обеих фаз). Если уточнённое название совпало с черновиком — событие `final` не публикуется (нечего анимировать).

### Две фазы генерации

Флаги в `session.meta`:

- `autotitle: "draft"` — черновик записан (по вопросу); рядом `autotitle_draft: <title>` — что именно записали.
- `autotitle: "done" | "fallback"` — окончательно (как раньше).

Условия (`gateway/autotitle.py`, вместо одного `needs_autotitle`):

- `needs_draft(title, meta)` — название дефолтное (`""`, `"Новый чат"`, `"gateway-сессия"`) и флага нет.
- `needs_refine(title, meta)` — либо флаг `"draft"` **и** `title == meta["autotitle_draft"]` (защита: если черновик успели переименовать вручную через CLI — не перетираем), либо старое условие (название дефолтное, флага нет — путь для чатов, где черновик не случился).

Поток:

1. `send_message`: после запуска run'а сервис спавнит `_autotitle_draft_bg(session_id, text)` — проверка `needs_draft`, генерация **только по вопросу** (существующий `generate_title` с `answer=""`), при сбое модели — `fallback_title(text)`. Запись: `title`, `autotitle="draft"`, `autotitle_draft=<title>`; publish `phase="draft"`. Повторная проверка условия в транзакции записи (гонка с быстрым уточнением: если флаг уже стоит — не пишем).
2. Завершение run'а (`_run_bg`/`_resume_bg`, существующий хук `_autotitle_bg`): проверка `needs_refine`, генерация по вопросу+ответу. Успех → запись `title`, `autotitle="done"`. Сбой модели: черновик есть → название не меняем (черновик лучше обрезки), ставим `autotitle="done"`; черновика нет → fallback-обрезка вопроса и `autotitle="fallback"`. Publish `phase="final"` — только если название реально изменилось. Флаги `"done"`/`"fallback"` окончательны — следующие run'ы ничего не перезапускают.

Ошибки обеих фаз — best-effort как раньше: warning в лог, ничего не роняют.

### Фронтенд

- `web/src/api/stream.ts`: `subscribeSessionEvents(baseUrl, token, onEvent)` — WS на `/sessions/events?token=...`, по образцу `subscribeRun`.
- `web/src/App.tsx`: эффект-подписка на весь жизненный цикл приложения: `session_title` → `setSessions(prev => prev.map(...))` (и топ-бар обновится сам через `active`). Реконнект: `onclose` → повторное подключение через 5 секунд (таймер чистится при размонтировании). Существующий busy-поллинг остаётся как fallback (WS мог порваться).
- Новый компонент `web/src/components/AnimatedTitle.tsx`: принимает `text`; при **изменении** текста печатает новое значение посимвольно (~25 мс/символ), при первом маунте рендерит сразу без анимации (иначе при загрузке списка все названия «печатались» бы хором). При `prefers-reduced-motion` — без анимации. Используется в строке чата в `Nav.tsx` и в заголовке топ-бара `App.tsx`.

## Тесты

Бэкенд:
- юнит `autotitle.py`: `needs_draft` / `needs_refine` (включая защиту от ручного переименования черновика);
- `SessionEventHub`: подписка получает publish, переполнение очереди дропает, отписка не ломает publish;
- сервисные: после `send_message` черновик записан (по одному вопросу — у фейк-провайдера нет блока «Ответ:»), после завершения run'а — уточнение; событие `session_title` приходит подписчику в обеих фазах; уточнение, совпавшее с черновиком, события не публикует; ручной rename черновика не перетирается;
- WS `/sessions/events`: 1008 без токена, событие доходит через `TestClient.websocket_connect`.

Фронтенд (vitest):
- `AnimatedTitle`: первый маунт — сразу полный текст; смена текста — печатается до конца (fake timers);
- `App`: событие `session_title` из застабленного WS (паттерн `FakeSocket` + `vi.stubGlobal`, как в `ChatScreen.test.tsx:211`) обновляет название в списке.

## Проверка вживую

`npm --prefix web run build` обязателен на машине с `serve` — иначе фичи в UI не будет (бандл в `web/dist` сам не пересобирается). Затем: новый чат → отправить сообщение → название печатается через ~1-2 сек, после ответа — дотачивается вторым «набором».

## Вне объёма

- Ручное переименование в UI.
- Другие типы событий в новом канале (создание/удаление сессий и т.п.) — канал спроектирован расширяемым, но публикуется только `session_title`.
- Перегенерация названия по ходу длинного чата.
