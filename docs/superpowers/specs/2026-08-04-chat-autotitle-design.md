# Автогенерация названий чатов по содержанию

**Дата:** 2026-08-04
**Статус:** утверждено

## Задача

Новые чаты в web UI называются «Новый чат» (хардкод клиента, `web/src/App.tsx:86`, `:133`) или «gateway-сессия» (дефолт сервера, `gateway/service.py:919`). Нужно, чтобы после первого обмена «вопрос → ответ» чат получал короткое осмысленное название по содержанию — как в ChatGPT/Claude.

Ручное переименование в UI в объём не входит (осталось только CLI: `svarog traces rename`).

## Решение (вариант A: хук на бэкенде)

Генерация целиком на стороне gateway; фронтенд не меняется вообще. UI уже поллит `GET /sessions` и рендерит `session.title` как есть (`web/src/App.tsx:115-126`, `web/src/components/Nav.tsx:130`) — новое название доезжает само в течение пары секунд после ответа. Пересборка `web/dist` не требуется.

### Архитектура

Новый модуль `src/svarog_harness/gateway/autotitle.py`:

- `generate_title(provider, task, answer) -> str | None` — один вызов `provider.complete([system, user], [])`, чистка результата;
- `clean_title(raw) -> str | None` — снятие обрамляющих кавычек, финальной точки, схлопывание переносов/пробелов, обрезка до 200 символов (лимит колонки `sessions.title`); пустой/мусорный результат → `None`;
- `fallback_title(task) -> str | None` — первые ~60 символов первого сообщения с обрезкой по границе слова.

Вызов из `GatewayService` в момент завершения run'а (`_publish_finished` / `_run_bg`, `gateway/service.py:592-615`, `:733-742`): fire-and-forget asyncio-задача, по образцу других фоновых задач сервиса.

### Поток

1. Run завершается. Сервис проверяет: название сессии дефолтное **и** `meta["autotitle"]` не установлен.
2. Если да — фоновая задача читает первый вопрос сессии (`runs[0].task`) и финальный ответ (`last_assistant_text`, `trace/recorder.py:310`), зовёт aux-модель (`auxiliary_provider(cfg.models, secret_store)`, `llm/openai_compatible.py:67`).
3. Результат чистится и пишется напрямую в сервисе (`GatewayService._autotitle_bg`, `gateway/service.py`), а не через `TraceRecorder.rename_session`: в одной транзакции повторно проверяется условие срабатывания (гонка с параллельным run'ом) и одновременно ставится `session.title` и `meta["autotitle"]` — `"done"` (LLM) или `"fallback"` (эвристика).
4. Поллинг UI приносит название в сайдбар и топ-бар.

### Условие срабатывания

Дефолтные названия: `"Новый чат"`, `"gateway-сессия"`, пустая строка. Флаг `meta["autotitle"]` — страховка от повторной генерации (в т.ч. если LLM вернула снова дефолтную строку). Любое значение флага (`"done"` или `"fallback"`) окончательное: следующие run'ы генерацию не перезапускают. Чаты, переименованные через CLI, имеют не-дефолтное название и не трогаются.

### Промпт и вход

Системный промпт (стиль по образцу `memory/autocapture.py:23-30`): короткое название диалога, 3–6 слов, на языке диалога, без кавычек и точки в конце, вернуть только название. Вход: первый вопрос до ~2000 символов + финальный ответ до ~1000. Если run упал и ответа нет — только вопрос.

### Обработка ошибок

Любая ошибка (aux-модель не сконфигурирована, сеть, пустой ответ после чистки) → fallback-обрезка первого сообщения. Ошибка логируется (warning), никогда не влияет на run и сессию. Нет и первого сообщения — название не трогаем, флаг не ставим.

## Тесты

- Юнит `autotitle.py`: `clean_title` (кавычки, точка, переносы, обрезка 200), `fallback_title` (обрезка по слову, короткий текст без обрезки, пустой вход → `None`).
- Сервисные с фейковым провайдером: после первого run'а название обновлено и флаг стоит; повторный run не перегенерирует; не-дефолтное название не трогается; исключение провайдера → fallback и флаг `"fallback"`.
- Фронтенд не меняется — фронтенд-тестов нет.

## Вне объёма

- Ручное переименование в UI (API `PATCH /sessions/{id}` + пункт меню) — отдельная фича.
- Догенерация названий старых чатов задним числом.
- Перегенерация названия по ходу длинного чата.
