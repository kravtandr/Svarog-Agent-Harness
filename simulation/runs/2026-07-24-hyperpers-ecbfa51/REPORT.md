## S30 — автозахват фактов о пользователе в профиль (#1)

**Сценарий:** chat из 3 ходов (персона P5), пользователь мимоходом роняет
устойчивое о себе («я продакт-менеджер в Северстали, по-английски тяжело —
пиши по-русски и покороче») + эфемерная задача (структура доклада). EOF
закрывает сессию → автозахват на `close()`.

### Найденный баг и фикс (`ecbfa51`)

Первый прогон на opencode: сессия отработала, но `memory_queue` пуст, профиль
не изменился. Диагностика (прямой вызов extractor'а на транскрипте) показала:
модель извлекла факты **идеально** —
`{"facts":[{"section":"Роль",...},{"section":"Язык",...},{"section":"Тон",...}]}` —
но обёрнутые в ```` ```json ````-фенсы, и `json.loads(content)` падал →
`_parse_payload` возвращал `[]`. Факты молча терялись.

**Фикс:** `_extract_json` снимает markdown-фенсы и берёт срез от первой `{` до
последней `}` (устойчивость к прозе вокруг). Регрессии:
`test_extract_facts_strips_markdown_fences`,
`test_extract_facts_tolerates_prose_around_json`. Весь набор зелёный.

### Пост-фикс — оба executor'а

**claude-code (эталон):** профиль после сессии:
```
## Роль — Продакт-менеджер в Северстали
## Язык — Предпочитает русский язык
## Тон  — Краткость в общении
```
Три факта → три отдельных `append`-коммита `user/profile.md` + `reindex`.
Эфемерика задачи (доклад/метрики/риски) в профиль **не попала**. Jail чист:
тронут только `user/profile.md` (+ autogen index.md/log.md).

**opencode:** тот же правильный результат автозахвата (Роль/Язык/Тон в
`user/profile.md`), **НО** дополнительно всплыла находка (см. ниже).

### Дедуп (claude-code)

Вторая сессия с теми же репликами против уже заполненного профиля → **0 новых
коммитов** (git HEAD не сдвинулся), профиль без дублей (ровно 3 секции).
Extractor отсёк уже известные факты. Дедуп живёт в `_facts_to_changes`
(host-side, model-independent) — на opencode вёл бы себя так же.

### Находка (не блокер): nudge провоцирует неряшливый ручной `remember` на deepseek

На opencode агент **сам** вызвал `svarog_remember` (пассивный nudge из
`_MEMORY_GUIDE` сработал), но deepseek сделал это неаккуратно:
- путь `memory/user/profile.md` — лишний префикс `memory/`, `resolve_memory_path`
  его принял (внутри jail) → создался осиротевший вложенный файл
  `memory/memory/user/profile.md`;
- содержимое — **эфемерика** («Раздел 'Риски' добавлен в структуру доклада»),
  а не долговечный факт.

claude-code так не делал (ручной remember не вызывал — чище). Мой **автозахват**
(aux-extractor) в обоих случаях сработал верно; засорил jail именно ручной
remember агента. Кандидаты на доработку: (а) уточнить формулировку nudge
(«путь — user/profile.md без префикса memory/; только устойчивые факты»);
(б) нормализовать/отклонять лишний `memory/`-префикс в `resolve_memory_path`.
Вынесено как отдельная находка, ядро фичи от неё не страдает.

## S31 — персона-директива меняет поведение (#3)

**Сценарий:** профиль предзаполнен поведенческими секциями (`## Тон` — «одним
абзацем без списков», `## Язык` — «всегда по-русски») + фактической `## Роль`
(дата-инженер). Один `svarog run` с вопросом **на английском**: «What are the
main tradeoffs between batch and streaming data pipelines?»

### Доставка директивы — детерминированно ЗЕЛЁНЫЙ (оба)

Host-side проверка `OpencodeAdapter.context_files(...)`: контекст-файл
`.config/opencode/AGENTS.md` содержит блок `# Персонализация (следуй как
инструкции)` со строками `Тон:` и `Язык:`; фактическая `## Роль` (дата-инженер)
в директиву **не вошла** — ровно по контракту (поведенческие → директива,
фактические → справка). Аналогично claude-code (`CLAUDE.md`).

### Следование директиве — поведенчески

- **claude-code (эталон):** на английский вопрос — ответ **по-русски, одним
  сплошным абзацем без списков**. Обе секции директивы соблюдены полностью.
- **opencode/deepseek:** ответ **по-русски** (⇒ `## Язык` дошёл и соблюдён —
  иначе откуда русский на англ. вопрос), но оформлен **нумерованным списком** —
  `## Тон` («без списков») deepseek не соблюл.

Вывод: **доставка** директивы верна на обоих (детерминированно + русский ответ
как поведенческое доказательство); **полнота следования** — вопрос качества
модели (claude-code полностью, deepseek частично), вторичен.

## S32 — Dream консолидирует профиль (#5)

**Сценарий:** профиль с внутренним конфликтом — `## Тон` («кратко, без списков»)
против `## Прочее` («просил развёрнутые подробные ответы со списками»). Прогон
джобы Dream воспроизведён host-side (тело `run_job`: `audit_memory` →
`build_dream_task` → `run_once(profile=DREAM)`), нативно на deepseek.

**Результат — ЗЕЛЁНЫЙ:**
- `build_dream_task` содержит пункт про `user/profile.md` (проверено в прогоне,
  не только юнитом);
- Dream (3 итерации) заметил смысловой конфликт и создал **memory-proposal**
  «Уточнение предпочтений в профиле» с внятным rationale: «Противоречивые
  указания в профиле могут запутать агента. Предлагаю заменить секцию „Прочее“
  на согласованное предпочтение, соответствующее стилю „Тон“»;
- операция — `replace_section` (**не** destructive delete непустой страницы,
  запрещённый кодом);
- `svarog memory proposals approve` + `flush` → противоречие устранено
  (`## Прочее` = «пользователь предпочитает краткие ответы»), правка — git-коммит
  `replace_section user/profile.md#Прочее`.

**Минорный артефакт (не код):** Dream-модель вложила заголовок в тело
`replace_section` → в профиле сдвоенный `## Прочее` (пустой + заполненный).
Косметика контента модели; консолидация по сути удалась. Кандидат: в гайд Dream
явно «content секции — без строки-заголовка».
