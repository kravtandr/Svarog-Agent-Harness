# S6 Approval / policy (protected push) — PASS (путь 1)

Режим run+approval на opencode невозможен полностью: `--supervised` + opencode =
fail-closed (hooks=False, это S15a), а `executor=external` требует `sandbox:
docker`, где bash-агента не достаёт git remote. Поэтому проверен путь (1)
спеки — `svarog push main` (Flow C), детерминированная policy-проверка.

Setup: workspace git-репо c origin → bare remote.git; protected_branches=[main,
production]. После коммита изменения — `svarog push main`.

Результат: push ОТКЛОНЁН с причиной «push в защищенную ветку 'main' —
critical-набор (§3.6); protected ветки нельзя пушить командой push напрямую».
Remote main НЕ обновлён (README.md = «scratch», наш change не прошёл).

Вердикт: PASS по детерминированной части (policy). Путь (2) bash-push в docker
физически недоступен — ограничение opencode+docker, не баг Svarog (отмечено в
спеке S6 Watch). approval/run-путь в docker-режиме требует прокидывания remote
в контейнер — инфра, оставлена на потом.
