# Группа retrieval / связка B (S34–S38), opencode

## Центральная инфра-находка: FTS не наполняется
После `svarog_remember` (append/create) + `memory: reindex` коммита таблица
`memory_fts` остаётся ПУСТОЙ (0 строк, а в свежей песочнице — даже не
создаётся). Спека S37: «индекс наполняется только дренажем памяти: после
svarog run, применившего заявку». В external/docker-конфигурации дренаж
reindex'ом FTS-синк не триггерит. `svarog memory flush` в песочнице пишет
«память не настроена» (не видит $MEM вне ws). Это инфра-баг конфигурации/
инициализации FTS в external-режиме, не поведение агента. Требует отдельного
разбора: где должен создаваться memory_fts и кто синкает в него при дренаже.

## S34 Поиск по содержимому — НЕ ВЕРИФИЦИРОВАН (FTS пуст)
Агент записал факт (ход1, в profile.md), FTS пуст. Ход2 — ответил из контекста
(0 итераций, профиль виден через AGENTS.md), `search_memory` НЕ вызван. Не
удалось проверить Assert (вызов search_memory → read_memory по пути) из-за
пустого FTS и контекстного ответа.

## S37 Writer → FTS — FAIL (FTS не наполняется)
ход1: svarog_remember append (в profile.md), reindex есть. FTS пуст —
SELECT path FROM memory_fts возвращает 0 строк. Assert «memory_fts содержит
путь новой страницы» провален. Корень: инфра FTS (выше).

## S38 Многошаговое расследование — НЕ ВЕРИФИЦИРОВАН (FTS пуст + chat)
search_memory идёт через MCP-бридж; при пустом FTS поиск ничего не вернёт.

## Итог связки B
Механика search_memory на opencode не верифицирована из-за инфра-бага FTS.
Это изолирует проблему: не «агент не вызывает search_memory», а «FTS пуст →
поиск бесполезен → агент отвечает из контекста». Рекомендация: завести
отдельный инфра-сценарий «FTS-синк при дренаже в external/docker-режиме».
